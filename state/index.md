# State Index — read this file first, and then read only what it points at

> **WHAT THIS FILE IS. It is an index, and it exists because `PHASE_SYSTEM.md` §State Growth says to make one: *keep summaries compact and bounded* and *if the continuity files grow too large, create a volume-level index and retrieve only relevant sections*.** The six state files had reached **2.6 MB and about 6,700 lines** after four volumes, and the volume close added to that and pruned nothing. This index is the bounded entry point the section of the handbook asks for. **The three comparisons that matter, measured rather than estimated, because this project has now been bitten six times by a figure read out of a file instead of a figure measured: `state/chapter-summaries.md` is 740 KB and the whole of Volume 04 is 681 KB, so the summary of a volume is larger than the volume; the six files together are 2.62 MB against 3.27 MB for all two hundred chapters, so the record is four fifths the size of the book it records; and `state/continuity.md` alone is 681 KB against 859 KB for Volume 01's fifty chapters, which is 79 per cent of a whole volume of prose sitting in one file that a prompt is told to open.**
>
> **WHAT IT IS NOT. It is not a summary of the novel, and it is not evidence.** Every count in it is a pointer to the place the count is kept, and where a count is printed here at all it is printed with the file and section that carries it. **A count in these files that carries no line number beside it is unverified, however confident the sentence around it is, and a line number here is a convenience and not a citation — sections are addressed by their heading, because a heading does not move when a paragraph above it is edited and a line number does.** **The sizes and line counts in the table below were measured on the day this index was written, and they are the reason for this file rather than a claim about the story: re-measure them rather than believing them.**
>
> **THE STANDING RULE, inherited from the Volume 03 close and not improved since: re-run the grep against the chapter files, and do not re-read the list.** A list in this project has been checked against the previous list instead of against the chapters six times in two hundred chapters, three separate lists were each short once, and the Volume 04 close found one short by ten. Reading a number out of a state file is the mechanism, not the accident.

## MACHINERY, AND THREE THINGS A HUMAN OR THE CONTROLLER HAS TO KNOW

**These are not story. They are defects in the project's own scaffolding, found by the review pass on the Volume 04 close, recorded here because the state files are the only place a future agent is certain to read.**

1. **`state/phase-ledger.json` is three volumes stale and this project did not change it, because the file is controller-owned and the writer and fixer are forbidden to edit it.** It reads `currentPhase: batch-0002`, Volume 01, Chapters 11–20, status `planned`, attempts 0. The truth is four volumes, two hundred chapters, twenty batches and four volume closes committed. The dispatch step reads that file, so the next phase selection is being made from a record that says the project is at Chapter 11. **The controller owns this repair. Nothing in the fiction depends on it and nothing in this index can fix it.**
2. **The Volume 04 close did not write `reviews/`, by the instruction in its own prompt, and so there is no `reviews/volume-04/` directory at all; Volume 03 is also missing its batch reviews for 0002 to 0005 and its volume audit, so the volume-audit gate has been skipped at least twice.** The Volume 04 volume audit is the next phase and it writes `reviews/volume-04/volume-audit.md`. **The Volume 03 audit is a real gap and is not to be papered over by writing a review of a phase that a reviewer never reviewed: it is a separate phase with its own prompt, and it should be run.**
3. **The generic continuation prompt at `workspace/continuation/next/PROMPT.md` told a writer to *plan the next volume and write its first batch*, which would have sent a writer into Volume 05 prose with no Volume 05 outline and no audit behind it.** The controller writes that file itself when no other incomplete phase exists, so it has not been edited here. **Creating `workspace/volume-04/volume-audit/PROMPT.md` is what prevents it being used, because the dispatcher prefers any other incomplete phase over the generic continuation, and the audit prompt says in its own first line that the volume is not to be planned before it is audited.**

## WHAT THIS INDEX DOES NOT DO

**It does not restate the plot, the money, the cast or the calendar, because a second copy of a figure is a second thing to go stale, and this file will itself be stale the moment a batch is written.** It does not claim that nothing is wrong. **It is a list of what was checked on the day it was written and not a claim that nothing is wrong**, and the six files it points at are the record, and the chapters are the evidence.
